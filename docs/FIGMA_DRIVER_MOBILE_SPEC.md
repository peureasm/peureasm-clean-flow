# Figma Driver Mobile Spec

## 목적
- 기사 역할에 최적화된 모바일 우선 UI를 피그마에서 바로 설계할 수 있도록 화면별 명세를 정리한다.
- 현재 코드베이스의 기사 라우트를 기준으로, 현장 작업 속도와 실수 방지를 최우선으로 한 UX 구조를 정의한다.

## 대상 라우트
- `/driver`
- `/driver/hospitals`
- `/driver/hospitals/[id]`
- `/driver/collection/[id]`
- `/driver/delivery/[id]`
- `/driver/history`

## 기사 UX 핵심 원칙
- 첫 화면에서 오늘 해야 할 일만 보여준다.
- 한 화면에는 한 가지 핵심 행동만 둔다.
- 병원 이동 중에도 읽기 쉬운 카드형 UI를 우선한다.
- 수량 입력, 상태 변경, 완료 확인은 큰 버튼과 짧은 문장으로 제공한다.
- 긴 설명보다 현재 상태, 다음 행동, 예외 여부를 먼저 보여준다.

## 모바일 설계 공통 규칙

### 레이아웃
- 기준 폭: `375 ~ 430`
- 상단 고정 헤더
- 하단 고정 CTA 영역 허용
- 카드 간 간격: `12 ~ 16`
- 본문 좌우 패딩: `16`

### 네비게이션
- 1뎁스 메뉴는 3개만 유지
  - 오늘 작업
  - 담당 병원
  - 작업 이력

### 카드 우선순위
- 작업 대기 카드
- 병원 정보 카드
- 수량 확인 카드
- 예외/차이 카드

### 액션 원칙
- `수거 시작`
- `수량 확인`
- `공장 입고 전달`
- `납품 완료`
- `사진 보기`

한 화면에 주액션은 1개만 크게 노출한다.

## Screen 1. 기사 홈

### 화면 목적
- 오늘 처리해야 할 업무를 바로 시작하게 한다.

### 상단 요약
- 오늘 수거 예정 병원 수
- 오늘 납품 예정 병원 수
- 미완료 작업 수

### 메인 섹션
- `지금 바로 해야 할 작업`
  - 가장 가까운 작업 1건
  - 병원명
  - 작업 종류
  - 예정 시간
  - 바로가기 버튼
- `오늘 일정`
  - 시간순 카드 리스트

### 피그마 구조
- 상단 KPI 3개
- 큰 우선 작업 카드 1개
- 작은 일정 카드 리스트

### 핵심 컴포넌트
- `Driver/KpiMini`
- `Driver/TaskHeroCard`
- `Driver/TimelineCard`

## Screen 2. 담당 병원 목록

### 화면 목적
- 기사에게 배정된 병원을 빠르게 찾고 들어가게 한다.

### 상단
- 검색
- 전체 병원 수

### 리스트 카드 정보
- 병원명
- 주소
- 연락처
- 오늘 예정 작업 여부
- 상세 진입 버튼

### 피그마 포인트
- 병원명과 주소 구분이 선명해야 한다.
- 오늘 일정이 있는 병원은 카드 좌측 상단 배지로 강조

## Screen 3. 병원 상세

### 화면 목적
- 병원 기본 정보와 지금 할 수 있는 작업을 함께 보여준다.

### 상단 요약
- 병원명
- 주소
- 담당자 연락처
- 오늘 작업 상태

### 메인 카드
- `오늘 해야 할 작업`
  - 수거 예정
  - 납품 예정
  - 최근 요청

### 빠른 액션
- 수거 처리 시작
- 납품 처리 시작
- 요청 이력 보기

### 피그마 포인트
- 관리용 병원 상세가 아니라 작업용 병원 상세로 설계
- 버튼은 2~3개만 유지

## Screen 4. 수거 처리 화면

### 화면 목적
- 병원 요청 물량을 기사 기준으로 빠르게 확인하고 저장한다.

### 상단
- 병원명
- 요청일
- 현재 단계 배지

### 품목 리스트
- 품목명
- 병원 요청 수량
- 기사 확인 수량 입력
- 오염/누수/예외 여부 토글

### 하단 고정 영역
- 임시 저장
- 수거 완료

### 예외 처리
- 차이 발생 시 경고 카드 노출
- 사유 입력 또는 사진 첨부 유도

### 피그마 포인트
- 숫자 입력은 한 손 조작 고려
- 표보다 반복 카드형이 더 적합

## Screen 5. 납품 처리 화면

### 화면 목적
- 최종 납품 수량을 확인하고 전달 완료 상태로 넘긴다.

### 상단
- 병원명
- 납품 대상 요청 정보
- 상태 배지

### 품목 리스트
- 품목명
- 출고 수량
- 납품 수량 입력 또는 확인

### 하단 고정 CTA
- 납품 완료

### 피그마 포인트
- 납품 단계는 수거보다 더 단순해야 함
- 최종 수량과 완료 버튼에 시선 집중

## Screen 6. 작업 이력

### 화면 목적
- 완료된 작업을 상태별로 확인한다.

### 상단 필터
- 전체
- 수거 완료
- 납품 완료
- 종결

### 리스트 정보
- 병원명
- 작업일
- 상태
- 간단 요약

### 피그마 포인트
- 기록 확인용이므로 정보 밀도는 높여도 됨
- 하지만 모바일이므로 1행 1카드 구조 권장

## 기사 모바일 IA 제안

### 1뎁스
- 오늘 작업
- 담당 병원
- 작업 이력

### 상세 이동 흐름
1. 오늘 작업
2. 병원 상세
3. 수거 또는 납품
4. 완료
5. 홈 복귀

## 기사 전용 컴포넌트 세트

### 공통 컴포넌트
- `Driver/MobileHeader`
- `Driver/KpiMini`
- `Driver/HospitalCard`
- `Driver/TaskCard`
- `Driver/QuantityCard`
- `Driver/StickyActionBar`
- `Driver/StatusPill`
- `Driver/ExceptionCard`

### Variant 제안
- `TaskCard`
  - collection
  - delivery
  - completed
- `StatusPill`
  - pending
  - active
  - warning
  - done

## 현장 특화 디자인 규칙
- 버튼 높이 `48~56`
- 숫자 입력은 큰 터치 영역 사용
- 대비는 높게 유지
- 상태색은 직관적이어야 함
- 본문 텍스트보다 수량과 상태가 먼저 보이게 한다.

## 코드 매핑 포인트

- 담당 병원 목록 -> `src/app/driver/hospitals/page.tsx`
- 병원 상세 -> `src/app/driver/hospitals/[id]/page.tsx`
- 수거 처리 -> `src/app/driver/collection/[id]/page.tsx`
- 납품 처리 -> `src/app/driver/delivery/[id]/page.tsx`
- 작업 이력 -> `src/app/driver/history/page.tsx`

2. 수거 처리 화면
3. 납품 처리 화면
4. 담당 병원 목록
5. 병원 상세
6. 작업 이력
