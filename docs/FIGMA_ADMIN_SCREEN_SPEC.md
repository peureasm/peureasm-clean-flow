# Figma Admin Screen Spec

## 목적
- 관리자 역할용 피그마 시안을 바로 제작할 수 있도록 화면별 구조와 우선순위를 명확히 정의한다.
- 현재 코드베이스의 관리자 화면을 기준으로, "운영 효율이 가장 높은 관리자 경험"으로 재설계할 때 필요한 화면 명세를 제공한다.

## 대상 라우트
- `/admin`
- `/admin/requests`
- `/admin/requests/[id]`
- `/admin/users`
- `/admin/hospitals`
- `/admin/hospitals/[id]`
- `/admin/drivers`
- `/admin/drivers/[id]`
- `/admin/discrepancies`
- `/admin/stats`

## 관리자 UX 핵심 원칙
- 첫 화면에서 운영 큐를 보여준다.
- 목록 화면은 검색보다 "즉시 처리 가능한 필터"를 우선한다.
- 상세 화면은 `요약 -> 체크포인트 -> 세부 탭` 구조를 유지한다.
- 상태 변화가 있는 화면은 반드시 "다음 행동" 버튼이 눈에 띄어야 한다.
- 병원 상세와 기사 상세는 같은 계열의 템플릿을 사용한다.

## 공통 레이아웃 규칙

### App Shell
- 좌측 고정 사이드바
- 상단 얇은 시스템 바
- 본문 최대 폭 `1440~1600`
- 카드 간 간격 `16~24`
- 섹션 단위 여백 `24~32`

### 공통 헤더
- 페이지 제목
- 한 줄 설명
- 우측 주요 액션 1~2개
- 목록 화면에서는 액션보다 필터 버튼 우선

### 공통 KPI 카드
- 4개 1세트 기준
- 구성
  - 아이콘
  - 라벨
  - 큰 수치
  - 보조 설명

### 공통 상세 템플릿
- 상단
  - 뒤로가기
  - 제목
  - ID/코드
  - 설명
  - 주요 액션 버튼
- 본문
  - 상단 KPI 카드 4개
  - 좌측 정보 카드 + 체크포인트 카드
  - 우측 탭 영역

## Screen 1. 관리자 대시보드

### 화면 목적
- 오늘 당장 확인해야 할 운영 이슈를 한눈에 보여준다.

### 상단 KPI
- 승인 대기 사용자 수
- 정산 대기 요청 수
- 미배정 병원 수
- 차이 발생 요청 수

### 메인 섹션
- `우선 처리 큐`
  - 승인 대기
  - 정산 대기
  - 기사 미배정
  - 차이 발생
- `최근 변경`
  - 최근 승인
  - 최근 종결
  - 최근 병원 등록

### 피그마 구성
- 4 KPI 카드
- 2열 레이아웃
- 왼쪽은 큰 큐 카드
- 오른쪽은 최근 활동 패널

## Screen 2. 전체 요청 내역

### 화면 목적
- 요청 흐름과 정산 상태를 한 번에 관리한다.

### 현재 코드 기준 핵심 반영
- `전체 / 진행 중 / 정산 대기 / 종결` 필터
- 정산 대기 금액 카드
- 목록 내 즉시 `정산 완료` 액션

### 화면 구조
- 헤더
  - 제목
  - 설명
  - 엑셀 다운로드
- KPI
  - 전체 요청
  - 진행 중
  - 정산 대기
  - 종결
  - 총 정산 대기 금액
- 필터 바
  - 상태 필터 칩
  - 검색
  - 날짜
  - 초기화
- 메인
  - 요청 리스트 테이블
- 우측 패널
  - 정산 요약
  - 우선 확인할 정산 대기 3건

### 테이블 컬럼
- 병원 정보
- 요청일
- 상태
- 정산 현황
- 최종 업데이트
- 액션

### 액션 우선순위
- 정산 대기면 `정산 완료`
- 공통 `상세 보기`

### 피그마 포인트
- 필터 칩을 탭처럼 보이게 하지 말고 "운영 뷰 전환"처럼 표현
- 정산 대기 행은 행 자체보다 정산 셀에서 강조

## Screen 3. 요청 상세

### 화면 목적
- 한 건의 요청을 끝까지 종결 처리할 수 있게 한다.

### 상단
- 요청 ID
- 병원명
- 요청일
- 상태 배지
- 엑셀 다운로드
- 정산/종결 처리 버튼

### KPI 카드
- 총 정산액
- 품목 수
- 최종 납품 수량
- 차이 여부

### 본문 좌측
- 공정 및 정산 현황
- 품목별 정산 상세 테이블

### 본문 우측
- 정산 가이드
- 타임라인
- 차이/AI 분석 결과

### 상태별 버튼 규칙
- `병원확인완료`일 때만 `정산 및 종결 처리`
- `종결`이면 읽기 전용 강조

### 피그마 포인트
- 금액과 상태를 헤더에서 바로 보여준다.
- 표 안의 수량 비교는 정렬된 숫자 컬럼으로 강하게 보인다.

## Screen 4. 사용자/권한 관리

### 화면 목적
- 승인 대기와 역할 변경을 빠르게 처리한다.

### 구조
- KPI
  - 전체 사용자
  - 승인 대기
  - 비활성 계정
  - 최근 7일 가입
- 필터
  - 전체
  - 승인 대기
- 검색
- 사용자 테이블

### 테이블 컬럼
- 이름
- 이메일
- 현재 역할
- 요청 역할
- 상태
- 액션

### 주요 액션
- 요청 역할 승인
- 역할 직접 변경
- 활성/비활성 전환

### 피그마 포인트
- 승인 대기 행은 배경톤을 살짝 다르게
- 역할 셀은 배지형
- 액션은 한 셀에서 과하지 않게 정리

## Screen 5. 병원 목록

### 화면 목적
- 배정 상태 기준으로 병원을 관리한다.

### 구조
- 검색
- 필터 칩
  - 전체
  - 배정됨
  - 미배정
- 카드 리스트

### 카드 정보
- 병원명
- 주소
- 담당 기사 상태
- 빠른 초대 링크
- 상세 보기

### 피그마 포인트
- 리스트보다 카드가 더 적합
- 미배정 병원은 기사 상태를 시각적으로 강조

## Screen 6. 병원 상세

### 화면 목적
- 병원 운영 상태를 한 화면에서 관리한다.

### 상단 KPI
- 최근 요청
- 담당자 수
- 사용 품목 수
- 담당 기사

### 좌측 카드
- 병원 정보
- 운영 체크포인트

### 우측 탭
- 요청 이력
- 병원 담당자
- 품목 설정
- 기사 배정

### 피그마 포인트
- 현재 구현된 상세 패턴을 관리자 상세 공통 템플릿으로 고정
- 체크포인트 카드는 "문제 없으면 조용, 문제 있으면 명확" 원칙

## Screen 7. 기사 목록

### 화면 목적
- 기사 계정 상태와 병원 배정 범위를 빠르게 파악한다.

### 구조
- 검색
- 필터 칩
  - 전체
  - 배정됨
  - 미배정
- 기사 카드 리스트

### 카드 정보
- 기사명
- 이메일
- 담당 병원 수
- 상태
- 기사별 초대 링크
- 상세 보기

### 피그마 포인트
- 카드 우상단 아이콘 액션은 `공유`, `더보기` 두 개만 유지
- 배정 0곳은 상태 카드처럼 강하게 보여준다.

## Screen 8. 기사 상세

### 화면 목적
- 기사 운영 상태와 최근 활동을 상세하게 확인한다.

### 상단 KPI
- 담당 병원 수
- 최근 요청 수
- 진행 중 요청
- 계정 상태

### 좌측
- 기사 프로필
- 운영 체크포인트

### 우측 탭
- 담당 병원
- 요청 이력

### 피그마 포인트
- 병원 상세와 같은 상세 템플릿 재사용
- 병원 상세와 색 계열만 다르게 운영 가능

## Screen 9. 차이 발생 모니터링

### 화면 목적
- 운영 위험이 있는 요청을 빠르게 선별한다.

### 구조
- KPI
  - 미해결 차이 건수
  - 오늘 신규 차이
  - 고액 차이
  - 장기 미해결
- 필터
  - 신규
  - 고액
  - 장기 미처리
- 리스트
  - 요청 ID
  - 병원명
  - 차이 사유
  - 차이 수량/금액
  - 현재 상태
  - 상세

### 피그마 포인트
- 관리자 화면 중 가장 경고성이 강한 색 사용 가능
- 빨간색 남발보다 강조된 오렌지/레드 포인트 사용

## Screen 10. 통계 리포트

### 화면 목적
- 운영 현황을 월/주 단위로 읽는다.

### 구성
- KPI 요약
- 상태별 분포
- 병원별 요청량
- 기사별 처리량
- 정산 추이

### 피그마 포인트
- 차트보다 상단 KPI와 필터가 먼저
- 관리자용 차트는 "예쁘게"보다 "비교가 쉽게"

## 피그마 컴포넌트 세트

### 반드시 공통으로 만들어야 할 것
- `Admin/PageHeader`
- `Admin/KpiCard`
- `Admin/FilterChip`
- `Admin/RightInfoPanel`
- `Admin/ChecklistCard`
- `Admin/DetailHero`
- `Admin/StatusRow`
- `Admin/TableToolbar`
- `Admin/EmptyState`

### 컴포넌트 Variant
- `KpiCard`
  - info
  - warning
  - success
  - neutral
- `FilterChip`
  - default
  - active
  - danger
- `ChecklistCard`
  - good
  - warning
  - action-needed

## 화면 간 통일 규칙
- 관리자 목록 화면의 KPI 높이는 모두 동일
- 상세 화면 좌측 카드 폭은 고정
- 탭 설명 바는 모든 상세 화면에 공통 적용
- 상태 배지는 `StatusBadge` 체계를 기준으로 동일 텍스트 사용
- 액션 버튼은 페이지당 1개 주액션, 1개 보조액션까지만 우선 노출

## 피그마 제작 우선순위
1. `전체 요청 내역`
2. `요청 상세`
3. `병원 상세`
4. `기사 상세`
5. `사용자/권한 관리`
6. `병원 목록`
7. `기사 목록`
8. `대시보드`
9. `차이 발생 모니터링`
10. `통계 리포트`

## 개발 매핑 포인트
- `전체 요청 내역` 시안 -> `src/app/admin/requests/page.tsx`
- `요청 상세` 시안 -> `src/app/admin/requests/[id]/page.tsx`
- `병원 상세` 시안 -> `src/app/admin/hospitals/[id]/page.tsx`
- `기사 상세` 시안 -> `src/app/admin/drivers/[id]/page.tsx`
- `사용자/권한 관리` 시안 -> `src/app/admin/users/page.tsx`
- `병원 목록` 시안 -> `src/app/admin/users/panels/AdminHospitalsPanel.tsx`
- `기사 목록` 시안 -> `src/app/admin/users/panels/AdminDriversPanel.tsx`
