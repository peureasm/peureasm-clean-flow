# Figma Hospital Screen Spec

## 목적
- 병원 역할에 최적화된 UI를 피그마에서 바로 설계할 수 있도록 화면별 명세를 정리한다.
- 현재 코드베이스의 병원 라우트를 기준으로, 요청 생성과 납품 확인, 정산 확인 흐름이 가장 자연스럽게 이어지도록 UX 구조를 정의한다.

## 대상 라우트
- `/hospital`
- `/hospital/new`
- `/hospital/requests`
- `/hospital/requests/[id]`
- `/hospital/settings`

## 병원 UX 핵심 원칙
- 복잡한 운영 기능보다 "지금 무엇을 해야 하는가"를 먼저 보여준다.
- 요청 생성, 요청 상태 확인, 최종 확인을 가장 짧은 동선으로 제공한다.
- 금액, 품목 수량, 현재 상태는 직관적으로 보여야 한다.
- 경고성 메시지는 필요할 때만 강하게 노출한다.
- 최종 확인과 같은 확정 액션은 사용자가 충분히 이해한 뒤 누르게 해야 한다.

## 병원 공통 레이아웃 규칙

### 전체 구조
- 상단 제목과 한 줄 설명
- 중간 KPI 또는 요약 카드
- 하단 카드형 리스트 또는 상세 정보
- 모바일 우선, 데스크톱에서는 1~2열 확장

### 공통 액션 규칙
- 페이지당 주액션 1개
- 보조 액션은 1개 이하
- 위험한 액션은 `AlertDialog`형 확인 UX

### 공통 상태 표시
- 진행 상태를 색상과 텍스트 둘 다로 구분
- 정산 관련 값은 항상 금액 카드 또는 요약 영역에서 고정 위치에 노출

## Screen 1. 병원 홈

### 화면 목적
- 병원 사용자가 현재 요청 상태를 한눈에 확인하고 바로 신규 요청이나 최종 확인으로 이동하게 한다.

### 상단 KPI
- 진행 중 요청
- 오늘 수거 예정
- 최종 확인 대기
- 이번 달 누적 정산

### 메인 섹션
- `지금 필요한 작업`
  - 납품 완료 후 확인이 필요한 요청
  - 최근 생성 요청
- `최근 요청`
  - 상태가 달라진 요청 3~5개

### 주액션
- `신규 요청 등록`

### 피그마 포인트
- 관리자처럼 데이터가 많지 않으므로 KPI보다 "해야 할 일 카드"가 더 중요하다.
- 첫 화면에서 사용자가 망설이지 않게 CTA를 크게 둔다.

## Screen 2. 신규 요청 등록

### 화면 목적
- 병원에서 세탁 요청을 빠르고 정확하게 생성하게 한다.

### 단계 구성
1. 요청일 / 시간
2. 품목 선택 및 수량 입력
3. 특이사항 입력
4. 요청 요약 확인

### 필수 요소
- 날짜 선택
- 선호 시간 선택
- 품목 목록
- 품목별 수량 입력
- 오염/누수/이중포장/라벨 여부
- 메모

### UI 원칙
- 규격화된 데이터는 선택형 우선
- 품목은 검색보다 병원 사용 품목 기준 리스트 노출
- 수량 입력은 카드 반복형

### 피그마 포인트
- 긴 폼처럼 보이면 안 되고, "작업 카드 묶음"처럼 느껴져야 한다.
- 최종 제출 전 요약 영역을 반드시 둔다.

## Screen 3. 요청 목록

### 화면 목적
- 요청 전체 이력을 상태별로 확인한다.

### 상단 필터
- 전체
- 진행 중
- 납품 완료
- 최종 확인 대기
- 완료

### 리스트 정보
- 요청일
- 상태
- 정산 금액
- 품목 수
- 상세 보기

### 정렬 기준
- 최근 변경 순

### 피그마 포인트
- 병원은 병원명 정보가 불필요하므로 요청 자체 정보에 집중
- 상태별 필터는 탭처럼 명확하게 보이게 한다.

## Screen 4. 요청 상세 및 최종 확인

### 화면 목적
- 병원 사용자가 납품 수량과 정산 금액을 검토하고 최종 확인을 수행한다.

### 상단
- 요청 ID 축약
- 요청일
- 상태 배지
- 정산 금액 카드

### 메인 구조
- 품목별 정산 상세 카드
  - 품목명
  - 단가
  - 최종 수량
  - 소계
- 최종 정산 합계
- 진행 타임라인

### 조건부 섹션
- `납품완료` 상태일 때
  - 최종 확인 안내 카드
  - 피드백 입력
  - 확인 버튼

### 확정 액션 UX
- `최종 납품 확인`
- 누르면 확인용 다이얼로그 노출
- 문구는 "이후 수정 불가"를 명확히 설명

### 피그마 포인트
- 관리자 요청 상세보다 더 단순해야 한다.
- 사용자 시선이 정산 금액 -> 품목 내역 -> 최종 확인 버튼 순으로 흐르게 설계

## Screen 5. 병원 정보 설정

### 화면 목적
- 병원 기본 정보와 사용자 초대 링크를 관리한다.

### 상단 카드
- 병원 사용자 초대
- 링크 생성 및 복사

### 본문 폼
- 병원명
- 주소 찾기형 입력
- 담당자명
- 연락처

### 하단 고정 액션
- `병원 정보 저장`

### 피그마 포인트
- 주소는 검색형 UI로 확실히 구분
- 저장 버튼은 모바일에서 하단 고정

## 병원 IA 제안

### 1뎁스
- 홈
- 요청 등록
- 요청 내역
- 병원 정보

### 보조 이동
- 홈 -> 최종 확인 대기 요청
- 요청 내역 -> 요청 상세
- 병원 정보 -> 사용자 초대

## 병원 전용 컴포넌트 세트

### 공통 컴포넌트
- `Hospital/PageHeader`
- `Hospital/KpiCard`
- `Hospital/ActionHeroCard`
- `Hospital/RequestCard`
- `Hospital/SettlementCard`
- `Hospital/TimelineCard`
- `Hospital/ConfirmPanel`
- `Hospital/StickyPrimaryAction`

### Variant
- `RequestCard`
  - pending
  - in-progress
  - delivery-complete
  - done
- `ConfirmPanel`
  - ready-to-confirm
  - already-confirmed
  - read-only

## 병원 역할 디자인 톤
- 신뢰감 있는 밝은 톤
- 관리자보다 더 단순하고 차분한 정보 밀도
- 상태 변화는 분명하지만 위압적이지 않게 표현
- CTA는 뚜렷하되 과도한 강조는 피함

## 코드 매핑 포인트
- 병원 홈 -> `src/app/hospital/page.tsx`
- 신규 요청 등록 -> `src/app/hospital/new/page.tsx`
- 요청 목록 -> `src/app/hospital/requests/page.tsx`
- 요청 상세 -> `src/app/hospital/requests/[id]/page.tsx`
- 병원 정보 설정 -> `src/app/hospital/settings/page.tsx`

## 피그마 제작 우선순위
1. 요청 상세 및 최종 확인
2. 신규 요청 등록
3. 병원 홈
4. 요청 목록
5. 병원 정보 설정

## 개발 반영 시 주의점
- 병원 사용 품목만 노출하는 구조를 유지한다.
- 정산 금액은 요청 상세와 목록에서 동일한 기준으로 보여야 한다.
- 최종 확인 UX는 실수 방지 문구와 되돌릴 수 없음 안내를 함께 보여야 한다.
- 병원 역할에는 관리자용 메타 정보나 운영 내부 용어를 최대한 숨긴다.
